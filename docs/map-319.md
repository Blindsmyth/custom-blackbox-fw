# Blackbox 3.1.9 firmware map

Built from a headless Ghidra 12.1.4 analysis of stock [`firmware/bins/3.1.9/BLACKBOX.bin`](../firmware/bins/3.1.9/BLACKBOX.bin) (`tools/ghidra_import.sh 3.1.9`). Names live in [`symbols/3.1.9.csv`](symbols/3.1.9.csv) and are applied to the Ghidra program on every run. Decompiled C of the functions discussed here is in [`decomp/3.1.9/`](decomp/3.1.9/). The full decompile, string and call tables are regenerated in `~/GhidraProjects/out/3.1.9/` and queried with `tools/decomp.py`.

Confidence: **sure** = read directly from code/data; **likely** = strong evidence but one step inferred.

**SDRAM allocators.** `FUN_0804436C` bump-allocates upward from the bottom (pointer at `0x2400008C`). Samples come from a stack that grows down from the top: `FUN_08044404` allocates and `FUN_08044470` frees back to a mark, with the top pointer at `0x24000088`. Its initial `0xC4000000` comes from the `.data` initialiser at `0x080F1E08`, and the reset path reloads it with `mov.w r2, #0xC4000000` at `0x08044498`. When the stack would pass the bottom allocator, `FUN_08044404` logs "ERROR: No more extended memory: crash" and spins at `0x0808A37C` (`b .`) until the watchdog resets: a preset that needs more sample memory than there is reboots the unit. (The first 3.1.R builds kept the top 1 MB for Rubber Band and hit this on full presets; it now uses no SDRAM.)

Patch state belongs in SRAM4 (`0x38000000`). It is clocked without setup and stock code never uses it. Its content survives a soft reset but is random after power-on, so it needs a magic word. 3.1.M put the state at DTCM `0x20000000`, which collided with the first stock DTCM allocation and left the preset list empty on the device. Backup SRAM needs `RCC_AHB4ENR.BKPRAMEN` + `PWR_CR1.DBP`. The old `ensure()` also waited for `PWR_CR2.BRRDY`, which only matters for battery retention and never set on the device. That is why every 3.1.F–L folder test silently fell back to `Presets`. The combined 3.1.Y image keeps folder state at `0x38000000` (`S_SIZE` `0x4930`), Warp flags at `0x38005000`, the slice pool header at `0x38006000`, and the Smooth/Capi/Vari voice slot at `0x38007000` (~30 KB, one owner).

## Tasks

CMSIS-RTOS v1 on FreeRTOS. `main` (`0x08044188`) creates three threads from the table at `0x080CFBB0`, then `osKernelStart`. `osThreadCreate` adds 3 to the CMSIS priority.

| Thread | Entry | CMSIS prio | Stack | Does |
| --- | --- | --- | --- | --- |
| `defaultTask` | `0x08043DEC` | Normal | 0x800 words | UI: input, `App` vtable (`App_Update` `0x080A2258`, key handlers), drawing |
| `audioTask` | `0x08043E64` → `0x08041470` | Realtime | 0xA00 words | Audio DMA half/full buffers |
| `pcmStreamer` | `0x08043E74` → `0x080743B0` | Normal | 0x800 words | Sample streaming from SD **and** `preset_cmd_dispatch` (all PresetMgr file work) |
| `USBH_Thread` | `0x08089B58` | AboveNormal | | USB host |

All confidence: sure.

Cross-task rule, from the call graph (sure): every FatFs call reachable from `defaultTask` goes through `BitmapFile_SaveToFile` (`0x0808BF90`, screenshot). Everything else (preset list, load, save, clean, sample streaming) runs in `pcmStreamer`. **Patch code that runs in the UI task must not call FatFs.** `SessionMgr_LoadBank` (`0x0809E218`) and `preset_screen_key` (`0x080BD928`) are UI-task code.

## FatFs

STM32Cube FatFs (R0.13/0.14 layout) behind `ff_gen_drv`. Configuration, read from the code:

| Option | Value | Evidence |
| --- | --- | --- |
| `FF_FS_TINY` | 1 | `f_write` copies partial sectors into `fs->win` (`FATFS+0x3C`) and sets `fs->wflag`; `FIL` has no buffer |
| `FF_FS_REENTRANT` | 0 | `FATFS` has no mutex field, `f_open` returns without unlock |
| `FF_FS_EXFAT` | 1 | `fs_type == 4` branches in `f_open`/`mount_volume`, 64-bit `FSIZE_t` |
| `FF_USE_FASTSEEK` | 1 | `FIL.cltbl` at `+0x50` |
| `FF_USE_LFN` | static buffer | `FILINFO.fname[256]`, LFN buffer pointer at `FATFS+0x0C` |
| `FF_MAX_SS` | 512 | Sector size is a constant `0x200` |
| `FF_CODE_PAGE` | 437 | `ff_uni2oem(…, 0x1B5)` |
| `FF_FS_LOCK` | 0 | No lock table calls |
| `FF_FS_RPATH` | 0 | `f_stat("Presets\\_Test\\..")` and `f_stat("..")` return `FR_INVALID_NAME` (6). `f_chdir` / `f_getcwd` are absent. `/` is still a separator: `Presets\\/_Test` opens `_Test` |

Struct sizes: `FIL` 0x58, `DIR` 0x58, `FILINFO` 0x120 (fname at `+0x1A`), `FATFS` 0x23C (window at `+0x3C`, `winsect` at `+0x38`). The firmware itself uses exactly these sizes (`memset` 0x58 / 0x120 in `SDMgr_ScanNames` and `SDMgr_FileSize`).

**Why 3.1.L corrupted the card:** there is one sector window per volume and no lock. A `f_write` from the UI task put log bytes into `fs->win` while `pcmStreamer` had the root directory sector loaded there. The directory was then written back with log text in it. Any FatFs call from a second task can do this, reads included, because a read also moves the shared window.

Diskio (`ff_gen_drv` dispatch): `disk_initialize` `0x080840F0`, `disk_status` `0x080840D8`, `disk_read` `0x08084118`, `disk_write` `0x08084138`, `disk_ioctl` `0x08084158`. These are the functions the off-device bench replaces.

API: `f_mount` `0x080864E8`, `f_open` `0x08086534`, `f_read` `0x08086866`, `f_write` `0x08086A06`, `f_sync` `0x08086C28`, `f_close` `0x08086D76`, `f_lseek` `0x08086D96`, `f_opendir` `0x080870F6`, `f_closedir` `0x0808718C`, `f_readdir` `0x080871A0`, `f_findnext` `0x080871F0`, `f_findfirst` `0x0808722E`, `f_stat` `0x0808724A`, `f_getfree` `0x08087290`, `f_truncate` `0x080873C8`, `f_unlink` `0x0808748E`, `f_mkdir` `0x08087558`, `f_rename` `0x080876C8`. (Earlier notes called `0x080871F0` `f_readdir`; it is `f_findnext`.)

SDMgr wrappers (object `0x240021A4`, mounted flag `+0x15`): `SDMgr_ScanNames` `0x08042F64` (`sd, dir, pattern, dirs, list`; directories are stored as `\name`), `SDMgr_FileSize` `0x08042E44` (`f_stat`; 0 when missing), `SDMgr_Mkdir` `0x08042E3A`, `SDMgr_Rename` `0x08042E24`, `SDMgr_CheckMount` `0x08042C90`, `SDMgr_ListDirs` `0x08042CD0` (clean/delete only).

`PresetMgr_BuildList(name)`: `SDMgr_CheckMount`, clear lists, scan root `*.xml` into `+0x304` and add them to the display list, `f_mkdir("Presets")`, scan `Presets` dirs into `+0x318` and add them without the `\`, post event 0x27, scan `Presets\<name>\*.wav` into `+0x2EC`, post 0x28, then 0x11 (list done) and 0x0F (free space).

`PresetMgr_Load(name)` → `PresetMgr_TryLoad` (`0x080918C8`): `doc_open(Presets\name\preset.xml)`. If that fails and a legacy root `name.xml` opens, it is **migrated**: `mkdir Presets\name`, save as `preset.xml`, delete the old file. If the name does not load at all, it loads the first display-list row that does (stock behavior that turned grouping folders into "load some other preset").

UI side (`defaultTask`): `App_Update` (`0x080A2258`) calls `PresetMgr_RequestList` from timers (`app+0x8CB0`, `app+0x8CB4`; `app+0x8CB9` = list request in flight), pops PresetMgr events with `PresetMgr_PopEvent` (`0x080905D0`) and turns event 0x11/0x13 into UI event `0x69` (list refresh). MIDI program change (input `0x6B`) calls `SessionMgr_LoadBank(app, n, 1)`.

`SessionMgr_LoadBank(app, index, flag)` (`0x0809E218`): rejects when `+0x390` is pending or the engine file queue is busy, then **clears the pads and stops voices first**, then `list_get(+0x32C, index)` and `PresetMgr_RequestLoad(name)`. A folder check therefore has to run at its entry, before any of that, and without FatFs.

## Implications for the folder patch

1. Keep the browse path in SRAM4 (`0x38000000`), with a magic word and a reset on every boot. Not DTCM (stock allocator) and not backup SRAM.
2. Anything that touches the card (group detection, `..`, scans) runs in `pcmStreamer`.
3. No patch code writes to the card.

3.1.P marks group folders during `BuildList` with two `f_stat`s per directory row on the first visit to a folder, then caches the group names. A later timer rebuild is 41 sector reads, same as stock (first visit is 4,227 vs 1,049). 3.1.O did the `f_stat`s on every rebuild, including the pads-screen timer, and crashed. Scratch buffers live in SRAM4 so they do not sit on the pcmStreamer stack.

The Load button (`App_HandleUiEvent` case 0x18, `0x080A1ABC`) calls `LoadBank(app, idx, 1)` and then `App_SetScreen(app, 2)`. Boot restore and MIDI call `LoadBank` directly. So the patch hooks the Load-button call site instead of the `LoadBank` entry. It posts a custom command 0x30 that pcmStreamer answers with either a list rebuild or an event 0x30, and the event replays the stock pair of calls.

Row commands (Save As / Rename / New / Delete / Clean) call `preset_path_join` with `in_load` clear, so without extra hooks they act on the loaded preset's folder while the row name comes from the browsed folder. 3.1.O wraps the dispatcher calls. See [preset-folders.md](preset-folders.md).

## Clip control panel (Main / Pos)

Pad INFO tabs are Main / Pos / LFO / Gran / Conf (`0x12F`–`0x133`). Page index is tab − `0x12F`. **Main** (page 0) is two fixed rows of four knobs. **Pos** (page 1) is a scroll list: the upper encoder selects the row, the lower encoder changes it. `InfoPage_Build` (`0x08098D40`) walks a ushort id list and stops on 0. Page stride is **0x48**. Sample Pos already has seven ids, so the list is not capped at four. Confidence: sure.

Type-`0x48` pads and type-`0x4C` engine objects use different tables, and `InfoPage_Build` then switches on `cellmode` (`0x8B`). Clip pad Pos is `DAT_08099094` = `0x080EF948`, page 1 at `0x080EF990`: `0x8D, 0xD2, 0x47, 0x94` then zeros; fifth ushort `0x080EF998` is free. Slicer pad Pos is `DAT_08099090` = `0x080EF7E0`, page 1 at `0x080EF828`: seven ids (`0x8D, 0xF2, 0xD2, 0xF3, 0xF4, 0x4E, 0xA2`) then a free eighth ushort at `0x080EF836`. Type-`0x4C` copies: Clip `DAT_08099080` = `0x080EF240` (Pos fifth `0x080EF290`), Slicer `DAT_08099084` = `0x080EF0D8` (Pos eighth `0x080EF12E`). Patching only a type-`0x4C` copy does not change the pad Pos list. Confidence: sure.

Param registry: `Param_RegisterAll` `0x0808C158` fills 500 × `0x1C` slots, pointer `0x2401F4FC`. Last stock id is `0x19B` (`sdsafemode`). Id `0x19C` is unused. `Param_RegisterEnum` `0x0808C0D8`, title `Param_Title` `0x0808E220` (returns +4), XML name `Param_XmlName` `0x0808E33C` (returns +0x18). Widgets are created only when `Param_Title(id) != 0`. `Param_Set` `0x08093ECC` updates an existing bag row and **does nothing** if the id is absent; `Param_Add` `0x08093EF6` inserts. Confidence: sure. **Bags are fixed-size:** `FUN_08093E6A(bag, n)` allocates `n*8` bytes once (SDRAM bump `FUN_0804436C`) and stores the capacity at `bag+0xC`. Every stock caller asks for 64 (templates `FUN_08093F20` / `FUN_0809481C`, bag ctor `FUN_080949E4`), and `Param_Add` returns silently when `count >= capacity`. A stock Clip template has 59 rows. `FUN_0809A830` memcpy's a cell's rows into the view bag with no capacity check, so all bags must grow together. 3.1.E: `hook_bag_size` at `0x08093E7C` turns 64 into 96. Confidence: sure (bench: Clip template 76 rows).

Clip audio is the type-`0x4C` engine (`FUN_08067fa4` / `FUN_08067648`), not `Sample_NoteOn`. The object is `FUN_0804436c(3000)` / `FUN_080640d0` (size `0xBB8`). Stock uses through `+0xBB0` (byte length-dirty). `+0x254` is the slicer flag (`cellmode==2`). Pad `+0x29` on the type-`0x48` object is 1 for Sample/Granular and 0 for Clip/Slicer; the clip object’s `+0x29` is the opposite. Normal Clip grains are started by `FUN_08065550` and the playback rate is stored at `grain+0x48` (`vstr` at `0x08065756`, `r3` = grain, `r4` = clip). `FUN_08065290` is the **slicer** grain path only and takes **10 args** (slice start/length on the stack). A wrapper that `push`es before that call shifts those args: click, no playback, empty waveform. `FUN_08064a94` writes `clip+0x258` (length/tempo constant). `tempo / (clip+0x258)` is the varispeed ratio. Message `0x39` with id `0x19C` is ignored by both switches unless hooked. Confidence: sure.

Warp id `0x19C` (`repitch` XML): `0` Stretch (stock grains, window `#256` at `grain+0x54`/`+0x5c`), `1` Repitch (scale `grain+0x48` by `clip+0xBB4`), `2` Smooth (WSOLA; Clip only), `3` Capi (Capicola keyframe stretch; Clip only; replaced Snap, which was slice-guided hops + short XF), `4` Vari (epoch-map grains; Clip only), `5` Grain (stock `Clip_StartGrain` path with window rewritten to 2048), `6` RB (Mixxx Rubber Band R2; Clip only; DSP in flash bank 2). Smooth/Capi/Vari/RB hook `FUN_080667b8` (`0x080667B8`) and share one stereo voice at SRAM4 `0x38007000` (magics `'SMTH'` / `'CAPI'` / `'VARI'` / `'RB  '`). Grain stays on stock grains: `hook_main_rate` / `grain_after` rewrite `+0x54`/`+0x5c`/`+0x58` when `clip+0xBB1==5` (Clip and Slicer). Smooth: window 2048 / hop 1024 / search ±160. Capi: 2048-keyframe ring per channel, leash 642 keyframes, punch fade 960; ignores the slice map. RB: bank-2 XIP + ~8 MB SDRAM arena; unpaired bank 2 falls through to stock Stretch. The slice map is at `clip+0x24C`, with its count at `+0x250`. Host A/B: `tools/stretch/proto --mode smooth|capi|vari|grain|naive`. RB cost: `tools/lab/rb/m7/RESULTS.md`. Confidence: sure (RB hardware soak pending).

Clip units and wrap (3.1.E, [clip-deck.md](clip-deck.md)): the engine plays one grain per **Sync unit**. `Clip_RecalcRates` sets `+0x208` = ticks per unit (int64, 960 ticks per beat), `+0x1FC` = samples per unit, `+0x210` = units. With Sync on (`+0x1F5`) `+0x240` = `+0x210`; with Sync None it is one unit, so the whole file is a single grain. `+0x230` = min(clip ticks, Quant Size ticks) is what the wrap re-syncs to. Note start passes the first unit to `Clip_StartGrain` at `0x08065A9A` (`r3`, 0 on Clip). In the lane render the next unit is `grain+0x64 + 1`. The Sync branch compares it at `0x08066C46` (`ldrd r2, r3, [r6, #0x240]; add; cmp r8; bhs`). At the limit, Loop Mode off or Trigger (`+0x1F8 == 1`) stops (`lane[9] = 1`); otherwise it re-syncs to `+0x230`, calls `RecalcRates`, and starts unit 0 at `0x08066CF2`. Confidence: sure.

Clip waveform screen (`FUN_080a54a0`, view object): knob widgets `+0x670` (encoder 1, top left), `+0x950` (2, bottom left), `+0xC30` (3, top right), `+0xF10` (4, bottom right). The corner order is taken from 3.1.Q's Mix layer and is unconfirmed on this screen. Sample binds `0x8F`/`0x90`/`0x91`/`0x92` there; the Clip refresh branch binds id 0 (`0x080A5806`–`0x080A583C`). `+0x47C8` is how many knobs take focus. The beat markers are set on every update (`0x080A5B0E`, `FUN_080c6e8c`, which clears the region flags `+0x239`/`+0x23A`). The bottom bar is `FUN_080a5480(view, mode == 2)`: `+0x11F0` (plain) or `+0x1568` (Slicer, with the `...` toggle `+0x1CE8`, id `0x4C`, which shows the Grid/Scan/Join/Split row `+0x2F8`). ## MIDI note path (pad trigger)

Traced for 3.1.E hot cues ([clip-deck.md](clip-deck.md) P2). Confidence: sure for the code path, likely for the ids' UI meaning.

1. **Parser.** `FUN_08044708(manager, packets, bytes)` reads 4-byte USB-MIDI packets and queues 5-byte events in the manager ring (`+0x4660`, write index `+0x4B64`, read `+0x4B60`). DIN In uses two more queues at `+0` and `+0x210`. `FUN_0804495E` pops all three.
2. **pcmStreamer poll (`FUN_0804CB1C`).** Each event becomes an engine message posted with `FUN_080518DC` (router `0x400`, broadcast): `0x90` → type **5**, `0x80` → 6, `0xB0` → 7, `0xE0` → 8, `0xA0` → `0xC`, `0xC0` → 9, `0xD0` → `0xB`. Message layout: `+0` type, `+8` channel (0–15), `+0xC` data 1 (note), `+0x10` data 2 (velocity). The UI's pad press posts `0x42` (`FUN_0804C61C(engine, key, note, …)`, note 0) through the same router.
3. **MIDI map node (`0x08050464`, not a Ghidra function).** It walks its event list and `tbh`-switches on type − 5: type 5 → `0x0804FE18` (note on), 6 → `0x08050254` (note off), 7 → `0x0804FACC` (CC), 8 → `0x0804FD44` (bend), `0x39` → param handler (`0x08050830`), `0x42` → `0x080507A6`, `0x43` → `0x08050770`. Pad index is `row × 5 + col` (≤ `0x13`; the bank byte is ignored). Per pad, 12 bytes at `node + 0x24 + 12·idx`: `+0` **`midimode`** (`0x6A`, "MIDI In": 0 None, 1–16 Ch 1–16, 17 Omni), `+4` **`padnote`** (`0xF5`, "Pad Note": 0 Default, else the note), `+8` pad key. `midiglobchan` (`0x76`) is `node+0x290`; `0x6A`/`0x76` set `node+0x344`, which makes the next event rebuild the channel-role table `node+0x334[16]` (`0x0804FC9C`): 1 = some pad's MIDI In, **2 = Global In** (Omni: all 16), 3 = Keys (`node+0x348`), 4 = Seq (`node+0x34C`).
4. **Note on (`0x0804FE18`).** Note 0 is dropped.
   - **Pad channel:** every pad whose `midimode − 1` equals the channel gets event type **2** with the **real note** (`+0xC`) and velocity (`+0x10`). Omni (17) never matches here.
   - **Global In:** if `node+0x334[channel] == 2`, a pad whose `padnote` equals the note is triggered; otherwise the default map `0x240150F0[note − 36]` (32 entries, notes 36–67) picks the pad, unless that pad has its own `padnote`. These triggers pass **note 0**, like a pad press. Notes 2–35 drive scenes/sequences; with `node+0x345` set, notes `0x44`–`0x63` do something else.
   - Keys / Seq channels go to the pads at `node+0x29C` / `node+0x298`.
5. **Pad event (`FUN_0804F744(node, offset, key, note, velocity, router, flag)`).** Builds type **2** (`+4` sample offset, `+8` key, `+0xC` note, `+0x10` velocity) for pads with index < 20, else type `0x18`, and routes it to that pad's list (`FUN_0805F32C`, list `router + (idx + 2)·0x604 + 4`). Note off is `FUN_0804F908` (type 3 / `0x19`). Msg `0x42` reaches the same function from `0x08050B84`, with velocity `node+0x2AC` when 0.
6. **Clip pad (`FUN_08067FA4`).** Type 2 (Toggle with the same note playing stops instead) → `FUN_08065908(clip, transport, offset, note, velocity, router)` at `0x080683AE` (`r3` = note). Types 5/`0x11`/`0x1A`/`0x8B` share the call at `0x08068656` (`r3` = note or 0); type `0x18` calls it at `0x080686CC` with note 0. Two stack arguments: a wrapper must not push before the jump. For a Clip the note is only stored (lane `+0x264`, `(note − 60)/12` at lane `+0x2B4`); Slicer uses note − 36 as the slice.

So a hot-cue note only reaches the voice start with its real note number when the Clip pad's own **MIDI In** channel (`midimode`) matches. Global In triggers carry note 0.

Clip launch state used by 3.1.E: `+0x28` playing (cleared by the render loop when no lane is active), lane 0 active `+0x260`, lane 1 active `+0x670`, `+0x218` Quant Size in ticks (int64, 0 = None), `+0xB79` quantized launch. At the next-grain call `0x08066CF2` the lane render has the grain's start tick, snapped to the unit grid (or to `+0x230` after a wrap), at `[sp+0x58]` (int64).

## Clip sample length

Question: how long can a Clip sample be in stock 3.1.9? Answer: there is no fixed length limit. Pads stream from the card through a block cache, and the practical limits are card speed, the WAV format and float precision in the Clip grain math. Traced 2026-10-18.

- **All pad loads stream (sure).** Every pad load, whether Sample, Clip or Slicer, goes through `FUN_0804C310(engine, key, path, 1, …)` → `FUN_08070DB0`, which queues pcmStreamer command `8 − flag` = **7**. Callers: `SessionMgr_FinalizeBankLoading`, `0x080A0CFC`, `0x080A0AC8`, `0x0809B044`. Command **8** (flag 0) preloads the whole file: it needs a contiguous run of free cache blocks and logs "Unable to allocate memory for wave". Only the preview/audition path at key `0x401` uses it.
- **Sample manager (`FUN_08073740`, pcmStreamer).**
  - 576 (`0x240`) wave slots of `0x170` bytes, table at `mgr+0x4348`, key → slot map at `mgr+0x434C`.
  - Command 7 marks a slot pending (`+0x164`) and queues it (`mgr+0x8FA8`, at most `0x240`).
  - The WAV header is parsed by `FUN_08076AF4`: PCM (1), float (3) and extensible (`0xFFFE`). It has **no length check**: data bytes go to `+0x10` (uint32), block align to `+0x24`, channels to `+0x1A`.
- **Block cache.**
  - 615 (`0x267`) cache entries of `0x1C` bytes at `mgr+0`. Each entry is **8192 frames (`0x2000`) of one channel pair**. A wave uses `ceil(channels/2)` pairs (`+0x160`, at most 4).
  - Total: 615 × 8192 = 5,038,080 frames per pair, about **105 s at 48 kHz** (114 s at 44.1 kHz) shared by all pads.
  - Loading a block (`FUN_08071E7C` → `FUN_080713BC`) uses a 64-bit file offset: block align × (block << 13) + data start.
  - Eviction (`FUN_08071D64`) takes a free entry, otherwise the least recently used one (stamp `mgr+0x47CC`). Each wave's first 3 blocks stay resident, or only the first 1 once more than 87 waves are loaded (`mgr+0x8FA4`), so pads start instantly.
- **Block lookup (`FUN_080721F8`).**
  - Blocks 0–1499 (`0x5DC`) use a per-wave direct map (`*(mgr + (slot + 0x219C)·4)`), which is 1500 × 8192 frames = 12.3 M frames, **4:16 at 48 kHz / 4:38 at 44.1 kHz**.
  - Later blocks still work. They are found through a 12-entry recent list in the wave slot (`+0x30`), and otherwise by a linear scan of all 615 entries.
  - So past about 4:16 every block lookup that misses the recent list costs up to 615 compares. Slower, not broken. Not measured on the device.
- **Clip engine positions.**
  - `Clip_StartGrain` computes the grain start as `(int)((float)unit × (float)spu)` (`clip+0x1FC`, float) and stores it as int64 at `grain+0x38`. The read counter is 64-bit.
  - The float product is exact only up to 2^24 frames: 5:49 at 48 kHz, 6:20 at 44.1 kHz. After that, grain starts are off by up to 1 frame (to 11:39 at 48 kHz), then 2, 4 and so on.
  - Grains are only 256-sample crossfaded, so this should stay inaudible for a long time. It is a timing fact, not a hard limit. Confidence: likely.
  - Unit count, ticks and Quant Size are 32/64-bit (`+0x208` int64, `+0x240` uint32).
- **Format ceiling.** The WAV data size is uint32, so a file is at most 4 GB: about 6.2 h of 48 kHz 16-bit stereo, or 3.1 h at 24-bit. FatFs has exFAT on (`FF_FS_EXFAT`, 64-bit `FSIZE_t`), so the card side is not the cap.

**Read path and block requests (traced for the 3.1.E cue prefetch, sure).**
- **The provider.** A pad's sample ref (`clip+0x24` → 0x34-byte ref, built by `FUN_08055004`: 576 refs, `+0x20` provider, `+0x24` wave id) points at the pcmStreamer manager itself. Its vtable is `0x080E9604`:
  - `+8` read (`0x08074A00`): copies frames from cached blocks; on a miss it **zero-fills** and counts the miss at `mgr+0x8F70`. That is the audible gap.
  - `+0xC` read variant (`0x08074748`).
  - `+0x10` **seek** (`0x08074CE8`).
  - `+0x14` frame count (`0x080708FC`, struct return).
  - `+0x18`: `+0x1C` of the wave slot.
  - `+0x20` channels.
- **Seek.** `FUN_0806375C(ref, frame)` → seek → `FUN_08074554(mgr, wave, frame >> 13)`. There is **no read head**. For blocks *b*..*b*+2 it either refreshes the LRU stamp (`+0x10` = `mgr+0x47CC`++) of a cached block, or queues a type-4 request `{wave, block}` in the ring at `mgr+0x47F8`. It then wakes pcmStreamer (`FUN_08088402`).
  - The ring has 128 × 16 bytes (write `+0x4FFC`, read `+0x4FF8`). The duplicate check looks back only at the last two entries, and there is no overflow check.
  - `Clip_StartGrain` calls it at grain start (`start − 8`). The read path calls it with the block it just read, which gives the 3-block read-ahead.
- **pcmStreamer side.** It drains the ring in `FUN_080740B4` from its loop. For a type-4 request it refreshes an already cached block, or loads it with `FUN_08071E7C`.

3.1.E uses this for hot cues. `deck_cue_note` seeks the target when it sets the pending jump. `deck_wrap_unit` repeats the seek on every grain until the jump, which keeps those blocks the youngest in the cache. Repeats are skipped while 32 or more requests are waiting.

Implications for 3.1.E: the 512-beat cap on the Clip region and cue knobs (`MAX_BEATS` in `deck.c`) is only ours. Raising it needs an "end of file" sentinel that stays compatible with saved `512`, and cue knobs that are not a label list. A hot-cue jump can land on a block that is not cached. Stock only requests it when the grain starts, and a miss is zero-filled. 3.1.E therefore prefetches the target from the cue note on (see above).

## Master compressor

Audio is 48 kHz with 128-frame float blocks.

**Master render `FUN_08053164`.** In order:
1. Voices.
2. Delay (bus 10) and Reverb (bus 11) returns summed into bus 0.
3. Master EQ node (`SE+0x28D8C`).
4. DJ FX.
5. `bl FUN_0804EDDC` at `0x08053CA0`, only while `globcomp` 0xB4 is on (`SE+0x28D60`).
6. Output volumes.
7. ±1.0 clamp to 20 bits.

**Compressor object (`SE+0xFC40`, ctor `FUN_0804F010`).**
- Settings:
  - `+0x428` threshold dB (−4)
  - `+0x42C` ratio (4)
  - `+0x430` input gain dB (−4)
- Processing, in order:
  1. 128-sample stereo RMS (`FUN_08075520`/`48`), converted to dB (`FUN_0805F788`).
  2. Hard-knee gain computer.
  3. Linear gain ramp at `+0x434`: `FUN_0804C05C` sets the target and `FUN_0804BE40` applies it. Ramp +0x14 is attack and +0x18 release, in samples; they are read only when a segment starts. The values are `+0x448` = 480 and `+0x44C` = 12000.
  4. Per-block peak limiter at 0 dBFS: ramp `+0x454`, attack `+0x468` = 192, release `+0x46C` = 36000.

**Params.**
- Ids 0x12F–0x13B (`cattack`, `crelease`, `cthreshdb`, `cratio`, `eratio`, `cautomakeup`, `ckneedb`, `clookahead`, `cautorel`, `commode`, `cwetdry`, `cgaindb`, `cbypass`) are registered by `Param_RegisterInt` `FUN_0808C12C(reg, id, fmt, title, min, max, xml)` but unused in stock.

- Formats:
  - 7 = milli-dB, printed by `FUN_080C4130` as "-4.0"

  - 0x10 = "%ld"

## Granular pad engine

From the decompile (`~/GhidraProjects/out/3.1.9/all.c`) and capstone; not checked on the device. For the Warp Lab model and a tempo-synced variant.

**Where it runs.** Inside the ordinary type-`0x48` pad (the Sample object: constructor `FUN_08055450`, process `FUN_080596b0`). Cell mode `0x8B` = 3 sets the Granular flag at `pad+0x589` (strb at `0x0805AE64`); the per-voice render is then `FUN_08057fe0` (bl at `0x0805A9F2`) instead of the Sample render `FUN_08056fd0`. Up to 16 voices (`pad+0x2C..+0x68`, count `+0x6C`). Each voice has **8 grain slots** of 0x40 bytes at `*(voice+0x13C)`, of which N (`pad+0x58C`, 3..8) are active.

**Note-on** `FUN_08058548`:
- note ratio `voice+0x18` = 2^((note − root)/12) × fileSR/48000. Root is `pad+0x554` (Root Note `0xD0`), or 60 when that is 0.
- playhead `voice+0x10` (int64) = sample start + start mod; `voice+0x24` = forward (`!pad+0x10C` reverse).
- `voice+0x140` = note ratio × 2^(pitch/12000 + mod).
- phase references `voice+0x530` = transport samples, `voice+0x528` = playhead. Then every active grain is started (`FUN_08057ab0`, note-on flag set).

**Parameters** (Gran tab: `0x17C`, `0x180`, `0x17E`, `0x5D`, `0x5B`, `0x17F`):

| id | name | engine |
| --- | --- | --- |
| `0x17C` | Grain Size, 0..1000 | `pad+0x590` = max(840, ⌊(1200 + v·47.744)/840⌋·840) samples: 840..48720 in steps of 840 (= lcm 1..8). Default 4096. |
| `0x180` | Density, 0..1000 | d = v/1000 (`pad+0x5A0`). d < 0.5: N = 3, gap (`pad+0x5A4`) = (256 + ((0.5−d)·2)³·432000)/3 samples (85..144085). d ≥ 0.5: N = 3 + (d−0.5)·10 (3..8), gap 0. |
| `0x17E` | Scatter, 0..1000 | `pad+0x598` = table `0x080EB2A0`[v·96/1000], 97 exponential steps 0..39317 samples. A constant time offset, applied only when gap ≠ 0. |
| `0x5B` | Window, 0..1000 | `pad+0x594` = (v/1000)³ · 1,824,000 samples (0..38 s): the **random position range**. |
| `0x5D` | Speed, 0..2000 | X = v/1000 (0..2), modulatable (`voice+0x2BC`). The playhead scan rate. |
| `0x17F` | Pan Rnd, 0..1000 | `pad+0x59C` = v/1000. |
| `0x5C` / `0xD0` | Pitch (±24000 = ±24 st) / Root Note | pitch, and (root ≠ 0) the period lock below. |
| `0x57` | grainsize enum (legacy) | 1024..16384, reschedules every grain (`FUN_08057768`). |

`0x58` graincount and `0x59` spread have no case in the pad handler (likely unused).

**Scheduler.** Each grain restarts when its samples run out (`FUN_08057db8` → `FUN_08057ab0`). B = `voice+0x538` (transport samples), period S = N·gap + size; grain 0: B += S (= now at note-on); grain k: t = B + k·S/N (+ Scatter if gap ≠ 0). Onsets are S/N = gap + size/N apart. A grain waits t − size/2 − now samples, or starts late with the window skipped by min(now − (t − size/2), size − 1).

**Grain source position** (now = transport at block start):
- centre = playhead ± round((t − now)·X): + forward, − reverse.
- If Window W ≠ 0: centre += (rand()·rand()) % W − W/2.
- If Root Note r ≠ 0, the period lock: P = (int)(48000 / (32.703·2^((r−24)/12))) samples (r = 60: P = 183). Δ = ((centre − `voice+0x528`) mod P) − ((t − `voice+0x530`) mod P), wrapped into (−P/2, P/2], and centre −= Δ.
- start = centre − round(X·size/2) (+/− skip when late), clamped ≥ 0.

Grains always read forward; Reverse only turns the playhead.

**RNG.** `FUN_080c89d4`, the ANSI LCG: s = s·0x41C64E6D + 12345; return (s & 0x7FFFFFFF) >> 16. The seed is the global at `0x240000DC`, 1 at boot, shared with other callers.

**Grain playback:**
- Rate is `voice+0x140` captured at grain start. 1.0 is a straight copy; otherwise 4-point cubic (`FUN_080603ec`).
- Window: an 8192-entry Hann table at `0x080D26AC`, index (pos << 13)/size.
- Pan: L = cos(π/4·(pan+1)), R = sin(π/4·(pan+1)) (256-entry tables); pan = ((rand() % 256) − 128)·panrnd/128.
- Grains are summed with **no normalisation**: N Hann windows at hop size/N sum to N/2, so the level is ≈ 0.354·N per side (1.06× at N = 3, 2.83× at N = 8).
- Likely stock bug: at rate exactly 1.0, a grain that started mid-block advances by the whole block length at the next block, skipping its delay.

**Playhead over time** (`FUN_08057fe0`, every block):
- It advances by `voice+0x140` × X (capped at 8.0) per output sample, with the fraction kept at `voice+0x1C`. Below 0.001 it freezes (Speed 0 = freeze).
- Loop Mode (`pad+0x108`): None stops and releases at the sample end; Forward wraps to loop start; Bidirect flips direction. Trigger launch releases at a loop point.

**No tempo link:** the scheduler reads no BPM or ticks, and Sync `0x94` isn't on its pages. Every size and gap is a fixed sample count. The only tempo path is the per-voice LFO, which can be beat-synced and routed to Speed or Pitch.

**Mix and read:**
- Output goes through the Sample voice tail (`0x08055BB8` in `FUN_08055b04`): level/velocity ramp, pan, amp envelope `FUN_0806a6c0` (`voice+0x28`), filter `FUN_080762d8` (`voice+0xA8`), mix `FUN_0804da6c`. The same path as Sample pads.
- Each grain reads per block through `FUN_08063608(voice+0xC, L, R, n, pos)`, the stereo sibling of `FUN_08063634`, from the stream cache. No explicit seek, so a far jump (Window) can hit uncached blocks and play silent.

**Not settled:** who sends the internal param `0x188` (`pad+0x5B8`: grain base = file length × value/1000 instead of the playhead); whether transport+0 runs while stopped; which `FUN_080596b0` message cases are note-on vs retrigger; how mono files fill R.

**For a tempo-synced variant:** the natural link is the playhead scan rate. Set X so the playhead moves through the file at tempo / file tempo (as Clip's `clip+0xBB4`), and lock its position to the transport's tempo map the way 3.1.B's Bungee does. The grain size, density and scatter stay as they are.

## Clip lane: Level, pan, pitch (3.1.T)

What the grain reader `FUN_08066454` (called per grain from the lane render `FUN_080667B8`) applies, so a lane rendered by our own code (`tools/stretch/bungee/lane.h`) sounds like a stock one. `param_3` there is the grain at `clip + 0x30 + i·0x70`, `param_2` the lane.

- **Param objects.** `FUN_0806FB30(obj)` returns the sum of its sources, clamped to `[obj+0x28, obj+0x2C]`, and stores it at `obj+0x30`. Each source is a pair `{value pointer, amount}`: an index byte at `obj+0x20..0x23` picks the pair at `obj + idx·8`, and the value is `*(ptr+4) × amount`. The source count is `obj+0x24`; with no sources the function returns **0**, not the base. A Clip's base value is wired in as source 0 at amount 1. The FPU code is the reliable reading: Ghidra's C shows a constant. Confidence: sure (disassembly).
- **Level**, `lane+0x58`. Its base is `lane+0x90`, the normalised level written by param 4 (`1 + dB/64`, 0 at −64 dB, 1.1875 at +12 dB; 1.0 with Drive on, which applies Level after the lanes). Velocity is mod source 0xD and reaches Level only through a route. Gain = `FUN_08060880(level)`, which is 0 if ≤ 0, else 10^(min(12, 64·(x−1))/20). That function computes in doubles, so the bench stubs it. Mute: byte `clip+0xB78` sets the gain to 0. Confidence: sure.
- **Ramps.** 4 floats each, per grain, at grain `+0x40` (L), `+0x50` (R), `+0x60` (gain):
  - `+0x0` current value, `+0x8` target, `+0xC` samples left, stored as an int.
  - `FUN_08075FF0(target, ramp)` sets the length to |current − target| × 256, at most 256.
  - `FUN_08075E40(ramp, L, R, n)` runs the ramp; it skips the work when there's no ramp and the target is 1.
  - `FUN_08075FD0(a, b, ramp)` snaps the ramp at note-on.
  - Confidence: sure.
- **Pan**, `lane+0x0C`, in −1..1, with its source count at `lane+0x30`. It's a balance:
  - pan ≤ 0: R × (1 + pan).
  - pan > 0: L × (1 − pan).
  - It applies only if pan ≠ 0 or `lane+0x30 > 1`, and only when byte `clip+0xBA0` (output routing, param 0x95) is clear.
  - Confidence: sure.
- **Pitch.**
  - Param 0x5C, in milli-semitones (±24000), is stored raw at `clip+0xA80`.
  - Each block, per grain: rate = `2^(clip+0xA80 / 12000 + FUN_0806FB30(lane+0x94))` × grain rate (`grain+0x18` of `param_3`, i.e. clip `+0x48 + i·0x70`).
  - `lane+0x94` holds mods only, in octaves (±4).
  - `FUN_0805F728` is the 2^x table.
  - Confidence: sure.
- **Sync fields** (`Clip_RecalcRates` `FUN_08064A94`):
  - `+0x220` int64: the Sync size in ticks. `0xF0000` means Sync = Slice, 0 means None.
  - `+0x210`: unit count, `clip ticks / +0x220` (1 if Sync is off or the result is < 2).
  - `+0x1FC` (float): file frames per unit. `+0x204` (float): output frames per unit.
  - `+0x1F5`: Sync on.
  - With Sync = Slice, the lane render walks the slice table `+0x24C` / count `+0x250` instead of units.
  - Confidence: sure.
